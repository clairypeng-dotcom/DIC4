\subsection{Design Mindsets and Architectural Trade-Offs}

Grounded in FDA/USDA food safety guidance \cite{ref2}, \cite{ref11} and household waste literature, Food Guardian follows five core design mindsets: (1)~\textit{Food Safety First} (never sacrifice safety for waste reduction; flag incomplete storage context for manual review \cite{ref8}), (2)~\textit{Inventory Visibility} (ground LLM reasoning in live SQLite queries \cite{ref7}), (3)~\textit{Inventory-First Meal Planning} (score recipes against existing stock and urgency), (4)~\textit{Data-Driven Decision Making} (log granular usage and disposal events \cite{ref10}), and (5)~\textit{Personalized and Adaptive Planning} (recalculate portions dynamically as servings or stock change \cite{ref7}).

These mindsets resolve three key engineering trade-offs:
\begin{itemize}
    \item \textbf{Date Sorting vs. Context-Aware Safety:} Calendar dates drive reminder tiers, while a conservative rule validator separates \textit{Use By} from \textit{Best Before} labels and flags missing context without claiming sensor-level spoilage detection.
    \item \textbf{Fixed Menus vs. Dynamic Re-Planning:} Rather than locking users into rigid multi-day menus, the agent recomputes feasibility on demand from current SQLite state when headcount or stock changes \cite{ref7}.
    \item \textbf{Pure Rules vs. Pure LLM:} A \textit{Hybrid AI Agent} delegates natural language parsing and tool orchestration to the LLM while keeping arithmetic, unit conversion, and safety filtering strictly deterministic in Python \cite{ref4}, \cite{ref5}.
\end{itemize}

\subsection{System Overview and Component Architecture}

Food Guardian implements a nine-stage closed-loop workflow spanning: (1)~User/Application Scenario, (2)~Input \& Streamlit UI, (3)~Planner \& Reasoning Agent, (4)~Data Acquisition/Retrieval, (5)~Analytics Engine, (6)~Domain Knowledge Integration, (7)~Decision \& Validation, (8)~Output \& Interaction, and (9)~Feedback \& History. While the initial proposal planned only JSON knowledge lookup, the refactored architecture adds a local ChromaDB vector RAG index while keeping deterministic Python safety rules independent of retrieved text.

Figure~\ref{fig:architecture} illustrates the system architecture, and Table~\ref{tab:components} summarizes module responsibilities and verification status. In normal operation, user queries enter the Streamlit Chat Page and invoke the LangGraph workflow (\texttt{gemini\_graph.py}). Gemini calls read-only tools (\texttt{recommend\_recipes\_\allowbreak for\_servings\_tool}, \texttt{validate\_inventory\_\allowbreak safety\_tool}, inventory lookup, and knowledge retrieval) and synthesizes explanations grounded in returned quantities, deficits, and source attributes. When \texttt{GOOGLE\_API\_KEY} is absent, users can manually switch to local rule mode; failed API calls never silently claim local fallback.

\subsection{Data Model and Lifecycle Management}

SQLite persists state across three tables defined in \texttt{schema.sql}:
\begin{itemize}
    \item \texttt{inventory\_items}: Records \texttt{id}, \texttt{name}, \texttt{category}, \texttt{quantity} (REAL), \texttt{unit}, \texttt{purchase\_date}, optional \texttt{expiry\_date}, \texttt{date\_label\_type} (\texttt{use\_by}, \texttt{best\_before}, or \texttt{NULL}), optional \texttt{opened\_date}, \texttt{storage\_location}, and \texttt{status} (\texttt{active}, \texttt{consumed}, \texttt{wasted}).
    \item \texttt{consumption\_\allowbreak waste\_logs}: Stores immutable event snapshots (\texttt{item\_id}, \texttt{item\_name}, \texttt{category}, \texttt{quantity}, \texttt{unit}, \texttt{action\_type}, \texttt{reason}, \texttt{log\_date}). Deleting an erroneous entry sets \texttt{item\_id} to \texttt{NULL} while retaining snapshots, separating entry mistakes from actual waste.
    \item \texttt{recipe\_\allowbreak recommendations}: Reserved recommendation table; current matching runs dynamically over demonstration JSON (\texttt{data/knowledge\_base/\allowbreak recipes.sample.json}).
\end{itemize}
Atomic SQLite transactions reject overdraft deductions. Partially used items remain \texttt{active} until \texttt{quantity} reaches zero, so analytics must read \texttt{consumption\_\allowbreak waste\_logs} rather than final item status.

\subsection{Core Algorithms and Mathematical Formulations}

\subsubsection{Calendar-Day Date Reminders}
For an active item with threshold $t \ge 0$ and calendar-day difference $d = \text{expiry\_date} - \text{today}$, reminder state is partitioned as:
\begin{equation}
\begin{gathered}
\text{ReminderState}(d) = \hfill \\
\begin{cases}
\texttt{no\_date}, & \text{if } \texttt{expiry\_date} = \text{NULL}, \\
\texttt{passed\_date}, & \text{if } d < 0, \\
\texttt{expiring\_soon}, & \text{if } 0 \le d \le t, \\
\texttt{normal}, & \text{otherwise}.
\end{cases}
\end{gathered}
\end{equation}

\subsubsection{Serving-Scaled Quantity Validation}
Given recipe $r$ with base servings $S_{\text{base}}(r) > 0$, target servings $S_{\text{target}} > 0$, and base ingredient requirement $q_{\text{base}}(r, i)$, required quantity and normalized shortage are:
\begin{equation}
q_{\text{req}}(r, i) = q_{\text{base}}(r, i) \times \frac{S_{\text{target}}}{S_{\text{base}}(r)},
\end{equation}
\begin{equation}
q_{\text{miss}}(r, i) = \max\!\left(0,\, q_{\text{req}}(r, i) - q_{\text{avail}}(i)\right),
\end{equation}
across compatible units (e.g., $\text{g} \leftrightarrow \text{kg}$, $\text{mL} \leftrightarrow \text{L}$). Unconvertible units (e.g., \texttt{other}, bunch, pack) remain \texttt{unknown} and require manual confirmation.

\subsubsection{Safety Pre-Screening and Dual-Mode Ranking}
\texttt{safety\_service.py} classifies active SQLite batches as \texttt{blocked} (e.g., past \texttt{use\_by}), \texttt{review} (e.g., past \texttt{best\_before} or incomplete metadata), or \texttt{eligible} (no known exclusion rule triggered, not a safety certification). Both \texttt{blocked} and \texttt{review} batches are excluded from automatic stock counts. Feasible recipes are ranked using \texttt{quantity\_\allowbreak coverage} and \texttt{urgency\_score} under \texttt{ready\_now} (full compatible stock prioritized), \texttt{expiry\_first} (urgent eligible stock prioritized while flagging any shortage), or backward-compatible \texttt{balanced} mode.

\subsubsection{Unit-Consistent Waste Analytics}
To avoid cross-unit summation, \texttt{analytics\_service.py} groups logs by period, category, and compatible unit $u$, computing waste ratio only when $C_u + W_u > 0$:
\begin{equation}
\text{WasteRatio}_u = \frac{W_u}{C_u + W_u} \times 100\%.
\end{equation}

\subsubsection{Hybrid Agent Execution Flow}
Algorithm~\ref{alg:food_guardian} and Fig.~\ref{fig:flowchart} formalize the execution pipeline across three invariant gates: incomplete-data safety screening, deterministic post-LLM validation, and confirmation-gated ledger updates.

\begin{algorithm}[t]
\caption{Food Guardian Hybrid AI Agent Execution}
\label{alg:food_guardian}
\begin{algorithmic}[1]
\REQUIRE Query $Q$, SQLite inventory $I$, preferences $P$, servings $S_{\text{target}}$, mode $M \in \{\texttt{ready\_now}, \texttt{expiry\_first}, \texttt{balanced}\}$
\ENSURE Grounded recommendation $R$ with deficits and citations
\STATE Parse $(S_{\text{target}}, M, P)$ from $Q$ and select read-only tools
\STATE Retrieve active inventory $I_{\text{active}}$ and candidate recipes $D$
\IF{critical metadata (unit, label, servings) is missing}
    \STATE Prompt user or flag uncertain fields explicitly
\ENDIF
\STATE Retrieve preservation knowledge $K$ (JSON / ChromaDB) with sources
\STATE Classify batches into $\{\texttt{eligible}, \texttt{review}, \texttt{blocked}\}$ and filter to $I_{\text{usable}}$
\FOR{each candidate recipe $r \in D$}
    \STATE Scale $q_{\text{req}}(r, i)$ to $S_{\text{target}}$; normalize units and compute $q_{\text{miss}}(r, i)$
    \STATE Preserve incompatible units as \texttt{unknown}; evaluate $P$, \texttt{quantity\_\allowbreak coverage}, \texttt{urgency\_score}
    \STATE Reject $r$ if hard constraints are violated
\ENDFOR
\STATE Rank feasible recipes by $M$ (or explain stock/safety blockers if none)
\STATE Present read-only recommendation $R$ with deficits, disclaimers, and citations
\IF{user confirms actual cooking usage or disposal}
    \STATE Update $I$ and append \texttt{consumption\_\allowbreak waste\_logs} atomically
\ENDIF
\RETURN $R$
\end{algorithmic}
\end{algorithm}
